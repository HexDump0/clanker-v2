# Jev eval run: DeepSeek vs Jev vs Jev + Space Bunny

**Date:** 2026-09-30 · **Agent:** Claude Code (Opus 5.5) · **Type:** research

## What was done
- Created a Logfire read token (EU region; the human approved the device login) and stored it in
  `.env` as `LOGFIRE_READ_TOKEN`.
- Exported 120 frozen reviews, fetched 118 human per-attempt labels (read-only Dashboard GETs),
  ran Space Bunny investigations on all 120 (free, 0 errors), and ran Jev on the packet and bunny arms.
  OpenRouter spend was $0.04 in total.
- Fixed harness bugs found along the way: the vision span was mis-selected as the review span,
  README `##` headings were splitting packet sections, `result.usage` is a property not a method,
  the Logfire rate limit needed backoff, and JSON attributes needed tolerant parsing.
- Added the Space Bunny investigator (`evals/jev/investigate.py`) at the human's request, replacing
  reuse of the DeepSeek tool results. Added an always-reject baseline, AUC, and a threshold sweep to the report.

## Why / decisions made
- Results are in `AI/notes/jev-eval-results-2026-09-30.md`. Jev on the packet alone matches DeepSeek
  (AUC 0.70 vs 0.66, not significant) at about 37× lower cost and 75× lower latency. Space Bunny added nothing
  measurable. No system predicts humans well, because human rejections are dominated by strict AI-use
  judgments that the rubric under-specifies.

# Full v1 port: review agent, PDF reports, Slack, supervision

**Date:** 2026-07-19 · **Agent:** Claude Fable 5 (Claude Code) · **Type:** feature

## What was done

Ported everything live in v1 into v2 on top of the API-client/watcher foundation
(committed as `99d1cca`). v2 is now feature-complete relative to v1 minus the web UI
(deliberately dropped, see decisions).

- `config.py` — extended with AI provider settings: `AI_PROVIDER`
  (openrouter/hackclub), keys, `MODEL_NAME` (default bumped to
  `xiaomi/mimo-v2.5-pro`; the v1 default `mimo-v2-pro` is deprecated upstream),
  **`OPENROUTER_PROVIDER_ONLY`** (comma-separated slugs, e.g. `alibaba`) +
  `OPENROUTER_ALLOW_FALLBACKS` for provider pinning, `REASONING_EFFORT`, review
  concurrency, `PDF_DIR`, `GITHUB_TOKEN`, Slack tokens/channel, logfire.
- `review/models.py` — the 13-check rubric as pydantic models, **actually used as
  `output_type`** (fixes v1 pain points #2/#13: no message-log scraping, no
  all-caps prompt-begging). Check renamed `pre_flavortown_commits` →
  `pre_event_commits` (same Dec 25 2024 cutoff). Lenient validators for weak
  models: bare status strings, uppercase statuses, double-JSON-encoded `checks`.
- `prompts/` — ported the 4 live prompt files (system rewritten; precheck/checks/
  reviewer adapted; demo_guidelines verbatim). Tool list is accurate (pain point
  #11); a test enforces prompt↔toolset consistency forever.
- `review/tools.py` — 11 tools from v1's `review_tools.py` as a `ReviewTools`
  class: shared HTTP clients, GITHUB_TOKEN injected (no os.getenv), same tool
  names. `review_generate_pdf` is gone — not a tool anymore.
- `review/packet.py` — pre-fetches detail + dashboard-cached GitHub + README +
  prior reviews into the agent's user message.
- `review/pdf.py` — async `typst compile` (fixes blocking event loop, pain point
  #6); explicit output path from cert id (no contextvar, pain point #8). Template
  `templates/review_report.typ` copied verbatim.
- `review/runner.py` — packet → agent → validated ReviewOutput → PDF. Pure; no Slack.
- `slack/` — announcer (new-ship post, verdict edit, PDF upload), files/history
  ports, streaming bridge (chat_stream + task timeline), bolt Socket-Mode mention
  bot. Channel from `SLACK_CHANNEL` env (no hardcoded id). Chat agent gets a
  `run_review(cert_id)` tool that runs the real pipeline; the stream bridge
  uploads its PDF.
- `service.py` — replaces `run_all.py`: per-service supervisor with exponential
  backoff (pain point #9), reviews as bounded concurrent tasks
  (`MAX_CONCURRENT_REVIEWS`, pain point #5).
- `cli.py` — added `clanker review <cert-id>` and `clanker run`.
- `Dockerfile` — python3.13-slim + typst 0.15 + fonts + uv frozen sync.
- Tests: 22 passing (announcer with mocked Slack, packet, PDF via real typst,
  models, provider-pin config, prompt/tool consistency). Ruff clean.

## pydantic-ai 2.x gotchas hit (installed 2.13.0, v1 used 1.107)

- `Agent(instrument=True)` kwarg removed → rely on `logfire.instrument_pydantic_ai()`.
- `output_retries` kwarg removed → `retries` covers output validation retries.
- `result.usage()` is now a property, not a method.
- mimo-2.5 emits the nested `checks` object as a JSON *string* after long
  contexts → handled by a `model_validator(mode="before")`.

## Why / decisions made

- **Web interface (AG-UI chat + REST) not ported**: unauthenticated in v1 (pain
  point #15), unused relative to Slack. Add later behind real auth if wanted.
- **Browser tools, orphaned prompt pack, dead models** not ported — dead code.
- Provider pinning is config, not code: the human wants a new OpenRouter key
  locked to Alibaba Cloud Int. (`OPENROUTER_PROVIDER_ONLY=alibaba`). The v1
  OpenRouter key is over its limit (403) — that's why they're switching.
- Still advisory-only: nothing calls claim/submit. The gated client methods are
  the hook for a future human-approved flow.

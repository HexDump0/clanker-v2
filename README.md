# clanker v2

Ground-up rewrite of **sw-clanker**, the AI-assisted review bot for Hack Club
Shipwrights certifications. v1 lives in `sw-reviewer/` (read-only reference);
agent-facing project knowledge lives in [`AI/`](./AI) — start with
[`AGENTS.md`](./AGENTS.md).

## Architecture

```
src/clanker/
├── config.py        all settings in one pydantic-settings class (env/.env)
├── shipwrights/     typed async client for ds.shipwrights.dev/api/v1
│                    (mutating endpoints gated behind allow_mutations=True)
├── watcher.py       polls the PENDING queue; seen-state persists to disk
├── review/
│   ├── packet.py    pre-fetches detail + cached GitHub + README + prior reviews
│   ├── agent.py     pydantic-ai agents (review: structured output; chat: text)
│   ├── models.py    ReviewOutput — the 13-check rubric as a validated schema
│   ├── tools.py     11 investigation tools (GitHub, URL checks, page fetch)
│   ├── pdf.py       async Typst compile of the report
│   └── runner.py    packet → agent → ReviewOutput → PDF
├── slack/           announcements, verdict updates, PDF upload, @mention chat
│                    bot (Socket Mode, streaming)
├── service.py       supervisor: watcher + Slack, per-service restart w/ backoff,
│                    concurrent reviews (bounded)
└── prompts/         review rubric prompt pack (system, precheck, checks,
                     reviewer, demo guidelines)
```

Key differences from v1: talks to the real dashboard API instead of a proxy;
the verdict is the agent's **validated structured output** (no message-log
scraping); the PDF is generated by the runner from that output (no
prompt-begged tool call, no contextvar); state survives restarts; one crashed
service doesn't kill the rest. The bot is still advisory-only — it never
claims or submits verdicts (the client supports it, gated, for a future
human-approved flow).

## Setup

```sh
cp .env.example .env   # fill in SHIPWRIGHTS_SESSION, AI key, Slack tokens
uv sync
uv run playwright install chromium   # headless browser for demo page renders
```

To pin the LLM to a specific OpenRouter provider (e.g. Alibaba Cloud Int.):
`OPENROUTER_PROVIDER_ONLY=alibaba` (comma-separated slugs; requests fail loudly
rather than falling back unless `OPENROUTER_ALLOW_FALLBACKS=true`).

PDF reports need the `typst` binary (bundled in the Docker image).

Demo pages are rendered in headless Chromium and their screenshot described by a
vision model (`VISION_MODEL_NAME`, default `qwen/qwen3-vl-8b-thinking`) as extra
evidence for the review agent. Disable with `BROWSER_RENDER_ENABLED=false` if
Chromium isn't available.

## Usage

```sh
uv run clanker queue                 # pending queue + stats
uv run clanker show <cert-id>        # full cert detail as JSON
uv run clanker review <cert-id>      # one full review: verdict + PDF, no Slack
uv run clanker watch                 # watcher only (logs new certs)
uv run clanker run                   # everything: watcher + reviews + Slack
```

Docker: `docker build -t clanker .` — runs `clanker run`; mount a volume at
`/app/data` so watcher state and PDFs persist.

## Development

uv run pytest        # no network needed (fake dashboard via MockTransport)
